# QR Comms Backend

Backend for QR Comms written in Rust. Provides a reliable WebSocket "relay" for two devices to exchange messages between each other.

## Getting started

### Prerequisites

Rust and Cargo are required.

### Building and running locally

1.  Clone the repository.
2.  Run the application with `cargo run`.
    The server will start on `http://0.0.0.0:3000`.

## Docker

You can also build and run the application using Docker. A standard `Dockerfile` is provided. Example:

```bash
# Build the Docker image
docker build -t qr-comms-backend .
# Run the container
docker run -e SERVER_PORT=3000 -e MAX_CHANNEL_COUNT=10000 -p 3000:3000 qr-comms-backend
```

## API endpoints

### HTTP

* **`GET /health`**
    * **Description**: A simple health check endpoint.
    * **Response**: `OK`

### WebSocket

* **`/ws/{channel_id}`**
    * **Description**: Establishes a WebSocket connection for a participant to join or create a communication channel.
    * **`{channel_id}`** is a UUID string that uniquely identifies the channel, generated by the client.
    * **Connection flow**:
        * Clients connect to this endpoint, replacing `{channel_id}` with a valid UUID.
        * If the channel exists and has less than 2 participants, the client joins.
        * If the channel does not exist, a new channel is created, and the client joins as well
        * The connection is rejected if the channel is full (above 2 participants) or the server has reached its max channel limit
    * **Message types**:
        * Plain text messages are accepted.

## Configuration

The backend's behavior can be configured through environment variables:
* `SERVER_PORT`: The port on which the server will listen.
* `MAX_CHANNEL_COUNT`: The maximum number of active channels the server will allow (e.g. `10000`).
